    How to write an answer that gets full marks

    Examiners mark against a checklist. If your answer has every part below, you collect marks even if one detail is wrong. Never leave a question blank: a definition plus a labelled diagram already earns something.

    The 8-mark skeleton

    1. Definition in 2–3 lines. Underline the keywords.
    2. Diagram, always, with labels (head, NULL, top, front, rear, root…).
    3. How it works: the algorithm as numbered steps.
    4. Worked example: a small table or a sequence of drawings.
    5. Advantages / disadvantages or a comparison table.
    6. Applications and time complexity.
    7. One-line conclusion.

    About 15–18 minutes and 2–3 pages.

    The 15-mark skeleton

    1. Same skeleton, but every part is longer.
    2. Introduction + definition + why it is needed.
    3. Types or cases, each with its own diagram.
    4. Algorithm for every operation asked.
    5. A full worked example (every step drawn).
    6. Comparison table, complexity table, applications.
    7. Only if the question says “write a program”: add the code from the optional code box.

    About 30–35 minutes and 4–5 pages.

    1. Find the operations the scenario needs (add at the end? remove the latest? look up by key? shortest connections?).
    2. Pick the data structure that does those operations best.
    3. Justify it: “because it gives O(1) insertion at the rear” or “because it is LIFO”.
    4. Draw it for the scenario’s own data, and name one structure you rejected and why.

    Basics: structures, memory and Big-O

    The foundation unit. You’ll learn what a data structure is, how C groups data with structures, how a program borrows memory while it runs (malloc / free), and how we measure an algorithm’s speed (Big-O).

    Exam snapshot: what they ask

    • 8MDefine data structure and classify it. Model answer
    • 8MExplain structures: declaration, initialisation, accessing members, array of structures, pointer to structure. Model answer
    • 8MExplain malloc, calloc, realloc, free. Static vs dynamic allocation. Model answer
    • 8MTime & space complexity, asymptotic notations O, Ω, Θ. Model answer
    • 15MStore N student records using structures and dynamic memory. Model answer

    Part 1

    What is a data structure?

    A data structure is a way of organising data in memory so it can be used efficiently.

    Think of your wardrobe. You could throw every piece of clothing in one pile, and you’d still own the same clothes. But with shelves, hangers and drawers you find your jeans in two seconds. A data structure is the shelving for data. An algorithm is the step-by-step recipe you follow to use it (find, add, remove, sort).

    Programs store marks, names, bus routes, friend lists. How you store them decides how fast you can search, insert and delete. That’s the whole subject: pick the right shelf for the job.

    Classification

    TypeMeaningExamples

    Non-primitiveBuilt from primitive types. Hold many values.array, structure, list, stack, tree, graph
    ↳ LinearElements form a sequence, one after another.array, linked list, stack, queue
    ↳ Non-linearElements branch out (hierarchy or network).tree, graph

    Draw this tree in your answer. It is worth 2 marks on its own.

    Abstract Data Type (ADT)

    An ADT describes what a data structure does (its operations) without saying how it is built. For example, the Stack ADT promises push, pop, peek and isEmpty. You can build it with an array or with a linked list. The user doesn’t care which.

    Algorithm and its 5 properties

    An algorithm is a finite set of clear steps that solves a problem. Every algorithm must have:

    1. Input: zero or more values given to it.
    2. Output: at least one result.
    3. Definiteness: every step is clear and unambiguous.
    4. Finiteness: it stops after a finite number of steps.
    5. Effectiveness: every step is basic enough to actually carry out.

    “I O D F E”: Input, Output, Definiteness, Finiteness, Effectiveness. Say it as “I Owe Dad Five Euros”.

    Common operations on any data structure: traversal (visit each element), insertion, deletion, searching, sorting, merging.

    Part 2

    Structures (struct)

    A structure groups different types of data under one name.

    Your college ID card has your roll number (a number), your name (text) and your CGPA (a decimal). They are different kinds of data, but they all describe one student. A structure is that ID card: one name, many fields.

    An array can only hold items of the same type (50 marks, all int). A structure can hold items of different types. Each item inside it is called a member (or field).

    4. Pointer to a structure: the arrow operator

    A pointer is a variable that stores an address (where something lives in memory). When you have a pointer to a structure, you reach its members with the arrow -> instead of the dot.

    Dot for the thing, arrow for the pointer. s1.marks when you hold the structure itself, p->marks when you hold its address. Linked lists use -> everywhere, so this matters for Q22 too.

    Part 3

    Dynamic memory allocation (DMA)

    Dynamic memory allocation means getting memory while the program is running, exactly as much as you need.

    A static array is like booking a hall for 100 guests months in advance: if 30 come, 70 chairs are wasted; if 120 come, you’re stuck. Dynamic allocation is like ordering chairs on the day of the party, once you know the exact headcount, and returning them afterwards.

    Static vs dynamic allocation

    Static allocationDynamic allocation
    Memory fixed at compile timeMemory taken at run time
    Size can’t change: int a[100];Size can grow or shrink (realloc)
    Stored on the stackStored on the heap
    Freed automaticallyYou must free it with free()
    Can waste memory or run shortUses exactly what is needed
    Example: arraysExample: linked lists, trees

    The four functions live in <stdlib.h>. Each one hands back a pointer (an address) to the memory it reserved, or NULL if there wasn’t enough.

    malloc: “memory allocate”

    ptr = (int *) malloc(n * sizeof(int));

    Reserves one block of n × 4 bytes. The values inside are garbage (random leftovers).

    calloc: “contiguous allocate”

    ptr = (int *) calloc(n, sizeof(int));

    Takes two arguments (how many, size of each) and sets every byte to zero.

    realloc: “re-allocate”

    ptr = (int *) realloc(ptr, newSize);

    Changes the size of a block you already have. Old values are kept.

    free

    free(ptr); ptr = NULL;

    Gives the memory back to the heap. Setting the pointer to NULL afterwards is good practice.

    Reading the malloc line: sizeof(int) asks “how many bytes is one int?” (4). Multiply by n to get the total. (int *) tells C to treat the block as ints. Then always check: if (ptr == NULL) { printf("No memory"); }

    malloc vs calloc

    malloccalloc
    One argument: total bytesTwo arguments: count, size of each
    Memory contains garbageMemory is set to 0
    Slightly fasterSlightly slower (it clears memory)

    Two classic bugs

    You allocate memory but never free it, and then lose its address (for example, by pointing the pointer somewhere else). The memory stays reserved until the program ends.

    You free the memory but keep using the old pointer. It “dangles”, pointing at memory that isn’t yours. Fix: set it to NULL after free.

    Example: marks of n students

    Algorithm in plain English
    1. Read n, the number of students.
    2. Ask for memory for n integers using malloc. If it returns NULL, print “no memory” and stop.
    3. Read the n marks into that memory.
    4. Print them (or compute the average).
    5. free the memory and set the pointer to NULL.

    Part 4

    Time and space complexity

    Complexity tells you how the work grows as the input grows.

    Finding a friend’s name in a class register: if you read every name from the top, 60 students means up to 60 checks, 600 means up to 600. The work grows in step with the size: that’s O(n). If the register is sorted and you open it in the middle and keep halving, 600 names need only about 10 checks: that’s O(log n).

    • Time complexity: how many basic steps an algorithm takes, as a function of the input size n. We count steps, not seconds, because seconds depend on the computer.
    • Space complexity: how much extra memory it needs, as a function of n. Space = fixed part (code, simple variables) + variable part (arrays, recursion stack).

    Best, average and worst case

    Take linear search in an array of n items:

    CaseWhenComparisons
    BestThe key is the first element1 → O(1)
    AverageThe key is somewhere in the middleabout n/2 → O(n)
    WorstThe key is last, or not presentn → O(n)

    We usually quote the worst case, because it’s a guarantee.

    Asymptotic notations

    “Asymptotic” means “what happens when n gets very large”. Three notations describe it:

    Big-O: O(g(n))

    Upper bound, the worst case. f(n) = O(g(n)) if there are constants c > 0 and n₀ such that f(n) ≤ c·g(n) for all n ≥ n₀.

    “It will never be slower than this.”

    Omega: Ω(g(n))

    Lower bound, the best case. f(n) = Ω(g(n)) if f(n) ≥ c·g(n) for all n ≥ n₀.

    “It will never be faster than this.”

    Theta: Θ(g(n))

    Tight bound, the exact growth. f(n) = Θ(g(n)) if c₁·g(n) ≤ f(n) ≤ c₂·g(n) for all n ≥ n₀.

    “It grows exactly like this.”

    How to find the Big-O of any algorithm

    1. Count how many times the innermost statement runs, in terms of n.
    2. Keep only the biggest term: 3n² + 5n + 7 → n².
    3. Drop constants: 4n → n, n/2 → n.
    4. Loops one after another add (n + n = O(n)). Loops one inside another multiply (n × n = O(n²)).
    5. A loop that halves or doubles its counter runs log₂ n times → O(log n).
    OrderNameExamplen = 1,000
    O(1)ConstantAccess a[5], push/pop on a stack1
    O(log n)LogarithmicBinary search, search in a balanced tree≈ 10
    O(n)LinearLinear search, traversing a list1,000
    O(n log n)LinearithmicMerge sort, heap sort≈ 10,000
    O(n²)QuadraticBubble sort, two nested loops1,000,000
    O(2ⁿ)ExponentialTrying every subsetastronomical

    Order from fastest to slowest: 1 < log n < n < n log n < n² < n³ < 2ⁿ < n!

    “O(2n)” is not a final answer. Constants are dropped: write O(n). And don’t mix up the notations: Big-O is the upper bound, Omega the lower bound, Theta both.

    Linked lists: singly, doubly, circular

    A linked list is a chain of little boxes, each one pointing to the next. You’ll see why that beats an array for inserting and deleting, and you’ll perform every operation yourself, pointer by pointer.

    Exam snapshot: what they ask

    • 8MWhat is a singly linked list? Insert at beginning, end, and a given position. Model answer
    • 8MDelete from beginning, end, a given position; traverse; search. Model answer
    • 8MDoubly linked list with insertion and deletion. Model answer
    • 8MCircular linked list; compare SLL, DLL, CLL. Model answer
    • 15MLinked lists in full: all types and all operations. Model answer

    Part 1

    Why do we need linked lists?

    A linked list is a chain of nodes, where each node stores data and the address of the next node.

    A treasure hunt. Each clue (node) has a message (data) and tells you where the next clue is hidden (the pointer). The clues can be anywhere in the city; they don’t need to sit side by side. You only need to know where the first clue is (that’s head). The last clue says “The end” (that’s NULL).

    The problem with arrays

    • Fixed size. int a[100] stays 100 forever: wasted space or not enough.
    • Slow insert/delete in the middle. To insert at position 2 you must shift every later element one place right. 1000 elements → up to 1000 shifts.
    • An array needs one continuous block of memory.

    A linked list fixes all three. Nodes are created with malloc only when needed, they can sit anywhere in memory, and inserting means changing two pointers, no shifting.

    The node

    Each node is a structure (from Q21) with two members. The second one is a pointer to the same kind of structure, which is why this is called a self-referential structure.

    Array vs linked list

    ArrayLinked list
    Fixed size (static)Grows and shrinks (dynamic)
    Continuous memoryNodes scattered anywhere, joined by pointers
    Direct access: a[i] in O(1)Must walk from head: O(n) to reach the i-th node
    Insert/delete in middle: O(n) shiftingInsert/delete: change pointers, O(1) once you are there
    No extra memory per elementExtra memory for the pointer in every node

    Three types

    Singly (SLL)

    Each node points to the next one only. Travel in one direction.

    Doubly (DLL)

    Each node points to next and previous. Travel both ways.

    Circular (CLL)

    The last node points back to the first. No NULL, it loops.

    Part 2

    Singly linked list: every operation

    Every operation is just moving a pointer called temp and re-pointing one or two arrows.

    The golden rule of insertion: connect the new node to the list first (newNode→next = …), and only then change the old pointer. If you change the old pointer first, you lose the rest of the list. Try both orders in your head with the playground below.

    Insertion algorithms

    Insert at beginning O(1)
    1. Create newNode, store the data.
    2. newNode→next = head.
    3. head = newNode.
    Insert at end O(n)
    1. Create newNode, data in, newNode→next = NULL.
    2. If head == NULL: head = newNode, stop.
    3. temp = head; while temp→next ≠ NULL: temp = temp→next.
    4. temp→next = newNode.
    Insert at position pos O(n)
    1. If pos == 1, insert at beginning.
    2. Create newNode.
    3. temp = head; move temp forward pos − 2 times (it stops at node pos − 1).
    4. newNode→next = temp→next.
    5. temp→next = newNode.

    Deletion algorithms

    Delete from beginning O(1)
    1. If head == NULL: “underflow”, stop.
    2. temp = head.
    3. head = head→next.
    4. free(temp).
    Delete from end O(n)
    1. If head == NULL: stop. If only one node: free(head), head = NULL, stop.
    2. temp = head; while temp→next→next ≠ NULL: temp = temp→next.
    3. free(temp→next).
    4. temp→next = NULL.
    Delete at position pos O(n)
    1. If pos == 1, delete from beginning.
    2. temp = head; move it to node pos − 1.
    3. del = temp→next.
    4. temp→next = del→next.
    5. free(del).

    Traversal and search

    Traverse (display) O(n)
    1. temp = head.
    2. While temp ≠ NULL: print temp→data; temp = temp→next.
    Search for key O(n)
    1. temp = head, pos = 1.
    2. While temp ≠ NULL: if temp→data == key, report pos and stop; else temp = temp→next, pos++.
    3. If the loop ends, the key is not found.

    Forgetting the empty list case (head == NULL) and the single node case. Examiners look for them. Always write “If head == NULL, print underflow” as the first step of any delete.

    Part 3

    Doubly linked list (DLL)

    Each node has two pointers: prev to the node before it and next to the node after it.

    A train. Every coach is coupled to the coach in front and the coach behind, so you can walk through it in either direction. A browser’s Back and Forward buttons work the same way.

    Algorithms

    Insert at beginning
    1. Create newNode; newNode→prev = NULL.
    2. newNode→next = head.
    3. If head ≠ NULL: head→prev = newNode.
    4. head = newNode.
    Insert at end
    1. Create newNode; newNode→next = NULL.
    2. If head == NULL: newNode→prev = NULL, head = newNode, stop.
    3. Walk temp to the last node.
    4. temp→next = newNode.
    5. newNode→prev = temp.
    Insert after node temp (position pos)
    1. Walk temp to node pos − 1.
    2. newNode→next = temp→next; newNode→prev = temp.
    3. If temp→next ≠ NULL: temp→next→prev = newNode.
    4. temp→next = newNode.
    Delete node temp (any position)
    1. Walk temp to the node to delete.
    2. If temp→prev ≠ NULL: temp→prev→next = temp→next, else head = temp→next.
    3. If temp→next ≠ NULL: temp→next→prev = temp→prev.
    4. free(temp).
    • Traverse in both directions.
    • Delete a node when you only have a pointer to it (you can reach the previous node through prev).
    • Insert before a given node easily.
    • Extra memory: one more pointer per node.
    • Every insert/delete must update four links instead of two, so more chances to make a mistake.

    Part 4

    Circular linked list (CLL)

    The last node points back to the first, so the list forms a circle and has no NULL.

    Players sitting in a circle playing a card game: after the last player, the turn goes back to the first. A music playlist on repeat all and the CPU giving each program a turn (round robin) work the same way.

    Traversal can’t use while (temp != NULL): there is no NULL, so it would loop forever. Stop when you get back to head: do { print; temp = temp→next; } while (temp != head);

    Algorithms

    Insert at beginning
    1. Create newNode.
    2. If head == NULL: newNode→next = newNode; head = newNode; stop.
    3. Walk temp to the last node (temp→next == head).
    4. newNode→next = head.
    5. temp→next = newNode.
    6. head = newNode.
    Insert at end
    1. Create newNode.
    2. If head == NULL: newNode→next = newNode; head = newNode; stop.
    3. Walk temp to the last node.
    4. temp→next = newNode.
    5. newNode→next = head.
    Delete from beginning
    1. If head == NULL: underflow, stop.
    2. If head→next == head (one node): free(head); head = NULL; stop.
    3. Walk last to the last node.
    4. temp = head; head = head→next.
    5. last→next = head.
    6. free(temp).
    Delete from end
    1. If empty or one node: as above.
    2. Walk temp to the second-last node (temp→next→next == head).
    3. free(temp→next).
    4. temp→next = head.

    Circular doubly linked list: a DLL where the last node’s next points to the first and the first node’s prev points to the last. You can loop in both directions.

    Q23 · 8 marks infix → postfix is a sure-shot question

    Stacks and queues

    Two simple rules run half of computing. A stack serves the newest item first (LIFO). A queue serves the oldest item first (FIFO). Then we use a stack to check brackets and to convert expressions, the most predictable question in the paper.

    Exam snapshot: what they ask

    • 8MStack: operations, array implementation, overflow/underflow, applications. Model answer
    • 8MQueue, drawback of a linear queue, circular queue with example. Model answer
    • 8MCheck balanced parentheses using a stack. Model answer
    • 8MConvert infix to postfix (with table). Evaluate postfix. Model answer
    • 15MStacks and queues in full, with applications. Model answer

    Part 1

    Stack: Last In, First Out

    A stack is a linear data structure where insertion and deletion happen at one end only, called the top. Last In, First Out (LIFO).

    A stack of plates in the canteen. You put a clean plate on top, and you take a plate from the top. The plate you put last is the first one taken. You never pull a plate from the middle.

    Operations

    OperationWhat it doesTime
    push(x)Put x on topO(1)
    pop()Remove and return the top itemO(1)
    peek() / top()Look at the top item without removing itO(1)
    isEmpty()True when top == −1O(1)
    isFull()True when top == MAX − 1 (array version)O(1)

    Array implementation

    Use an array stack[MAX] and a variable top that holds the index of the top item. An empty stack has top = −1.

    PUSH(x)
    1. If top == MAX − 1: print “Stack Overflow”, stop.
    2. top = top + 1.
    3. stack[top] = x.
    POP()
    1. If top == −1: print “Stack Underflow”, stop.
    2. x = stack[top].
    3. top = top − 1.
    4. Return x.

    Trying to push into a full stack. Condition: top == MAX − 1.

    Trying to pop from an empty stack. Condition: top == −1.

    Linked list implementation

    Push = insert at beginning, pop = delete from beginning of a singly linked list (Q22). The head pointer acts as top. Both are O(1), and the stack never overflows until the computer runs out of memory.

    Applications of stacks

    • Function calls and recursion (the call stack)
    • Undo in editors
    • Browser back button
    • Balanced parentheses checking
    • Infix to postfix/prefix conversion
    • Evaluating postfix expressions
    • Reversing a word or a list
    • Backtracking (maze, DFS in Q25)

    Part 2

    Queue: First In, First Out

    A queue inserts at one end (the rear) and deletes from the other end (the front). First In, First Out (FIFO).

    The canteen line. New people join at the back (rear). The person at the front is served and leaves. Whoever came first is served first. No cutting in.

    OperationWhat it doesCondition to check
    enqueue(x)Add x at the rearOverflow if rear == MAX − 1

    ENQUEUE(x), linear
    1. If rear == MAX − 1: “Queue Overflow”, stop.

    The big drawback of a linear queue

    Once rear reaches the end of the array, the queue says “full” even if you have already dequeued items and the slots at the front are empty. Those slots are wasted forever. Try it: enqueue 5 items, dequeue 2, then enqueue again.

    Applications of queues

    • Printer job queue (print spooler)
    • CPU scheduling (first come, first served)
    • Breadth-first search in graphs (Q25)
    • Call-centre and ticket-counter waiting lines
    • Keyboard buffer
    • Sending data packets over a network

    Circular queue

    In a circular queue, the last position is connected back to the first, so rear wraps around and reuses the empty slots at the front.

    A round table with 5 chairs. When the last chair is taken, the next guest sits in chair 0 if it has been freed. The trick that makes this work in an array is the modulo operator: (rear + 1) % SIZE goes 0, 1, 2, 3, 4, 0, 1, …

    (rear + 1) % SIZE == front

    front == −1

    ENQUEUE(x)
    1. If (rear + 1) % SIZE == front: “Queue Overflow”, stop.
    2. If front == −1: front = rear = 0.
    3. Else: rear = (rear + 1) % SIZE.
    4. queue[rear] = x.
    DEQUEUE()
    1. If front == −1: “Queue Underflow”, stop.
    2. x = queue[front].
    3. If front == rear (only one item): front = rear = −1.
    4. Else: front = (front + 1) % SIZE.
    5. Return x.

    Balanced parentheses using a stack

    An expression is balanced when every opening bracket has a matching closing bracket of the same type, in the right order.

    Russian nesting dolls. The last doll you opened must be the first one you close. That “last opened, first closed” rule is exactly LIFO, so a stack is the perfect tool.

    Algorithm
    1. Create an empty stack.
    2. Scan the expression from left to right, one character at a time.
    3. If it is an opening bracket ( [ {: push it.
    4. If it is a closing bracket ) ] }: if the stack is empty → not balanced. Otherwise pop; if the popped bracket is not the matching type → not balanced.
    5. Ignore every other character.
    6. At the end: if the stack is empty → balanced, otherwise → not balanced.

    Traces to copy into your answer

    There are three ways to fail, and a full answer mentions all three: a wrong type (([)]), an extra closing bracket (a+b)), and an unclosed bracket left on the stack (((a+b)).

    Infix to postfix conversion

    Postfix puts each operator after its two operands, so the computer never needs brackets or precedence rules to evaluate it.

    NotationOperator positionExample

    Prefix (Polish)Before operands+ A B

    An old calculator that wants numbers first, then the button: “5, 3, plus”. Postfix is that order. Because the operator always comes after what it works on, there is never any confusion about what to do first.

    Precedence and associativity

    OperatorPrecedenceAssociativity
    ^Highest (3)Right to left: A^B^C = A^(B^C)
    * / %Middle (2)Left to right
    + −Lowest (1)Left to right
    Algorithm: infix → postfix using a stack
    1. Scan the infix expression from left to right.
    2. If the symbol is an operand (A, B, 5…): write it to the postfix output.
    3. If it is (: push it.
    4. If it is ): pop and output everything until (, then throw both brackets away.
    5. If it is an operator: while the top of the stack is an operator with higher precedence, or equal precedence and the incoming operator is left-associative, pop it to the output. Then push the incoming operator.
    6. At the end, pop everything left on the stack to the output.

    “Operands walk straight through, operators wait on the stack.” An operator is only allowed to sit on top of a weaker operator. If a stronger (or equal) one is on top, kick it out to the output first. Exception: ^ can sit on another ^.

    Worked examples

    Example 1: A + B * C
    Example 2: (A + B) * (C − D)
    Example 3 (classic exam question): A + B * (C ^ D − E) ^ (F + G * H) − I

    Infix to prefix (the reverse trick)

    Reverse the infix (swap ( and )), convert to postfix, reverse the answer.

    Two common slips: popping ^ when another ^ arrives (it is right-associative, so push), and forgetting to empty the stack at the end. Also, brackets never appear in a postfix answer.

    Part 6

    Evaluating a postfix expression

    Push numbers. When an operator comes, pop two, compute, push the result.

    Algorithm
    1. Scan the postfix expression left to right.
    2. Operand → push it.
    3. Operator → pop B (the top), then pop A. Compute A op B and push the result.
    4. At the end, the single value on the stack is the answer.

    The order matters for − and /. The first value you pop is the right operand. For 8 2 −: pop 2 (B), pop 8 (A), compute 8 − 2 = 6, not 2 − 8.

    Tree basics and terminology

    A tree is a non-linear, hierarchical data structure: a set of nodes connected by edges, with one special node called the root and no cycles.

    A family tree drawn upside down. The great-grandparent (root) is at the top. Children hang below their parents. People with no children are the leaves. Or think of folders on your laptop: C: drive → Documents → College → DSA.

    TermMeaning
    RootThe top node. It has no parent.
    EdgeThe link between a parent and a child. A tree with n nodes has n − 1 edges.
    Parent / childA node directly above / directly below another.
    SiblingsChildren of the same parent.
    Leaf (external node)A node with no children.
    Internal nodeA node with at least one child.
    DegreeNumber of children of a node. Degree of a tree = maximum degree of any node.
    Level / depthNumber of edges from the root (root is level 0; some books start at 1).
    HeightNumber of edges on the longest path from a node down to a leaf. Height of tree = height of root.
    Ancestor / descendantAny node on the path above / below.
    SubtreeA node together with all its descendants.

    Binary trees

    A binary tree is a tree where every node has at most 2 children, called the left child and the right child.

    Full (strict) binary tree

    Every node has 0 or 2 children, never exactly 1.

    Complete binary tree

    Every level is full except possibly the last, which is filled from the left.

    Perfect binary tree

    All internal nodes have 2 children and all leaves are on the same level.

    Skewed tree

    Every node has only a left child (left-skewed) or only a right child (right-skewed). It is really a linked list.

    Properties (with height h counted in edges)

    • Maximum nodes at level i = 2i.
    • Maximum nodes in a binary tree of height h = 2h+1 − 1.
    • Minimum height for n nodes = ⌈log₂(n + 1)⌉ − 1.
    • In a full binary tree, leaves = internal nodes + 1.

    Representing a binary tree

    Array (sequential)

    Store the root at index 0. For a node at index i: left child at 2i + 1, right child at 2i + 2, parent at ⌊(i − 1)/2⌋. Good for complete trees, wasteful for skewed ones.

    Linked

    Each node is a structure with three members: [ left | data | right ]. Missing children are NULL. Works for any shape.

    Tree traversals

    A traversal visits every node exactly once. The name tells you when the root is printed.

    Recursive algorithms
    1. Preorder(node): if node is NULL return; visit node; Preorder(left); Preorder(right).
    2. Inorder(node): if node is NULL return; Inorder(left); visit node; Inorder(right).
    3. Postorder(node): if node is NULL return; Postorder(left); Postorder(right); visit node.
    4. Level order: put root in a queue; while the queue is not empty: dequeue a node, visit it, enqueue its left and right children.

    Inorder of a binary search tree always comes out sorted. Use it to check your BST answers in the exam.

    Part 3

    Binary search tree (BST)

    In a BST, every node’s left subtree has smaller keys and its right subtree has bigger keys.

    The “guess my number” game. “Is it bigger than 50?” “Yes.” “Bigger than 75?” “No.” Each answer throws away half of the possibilities. A BST stores data so that every search is that game.

    Search(key)
    1. Start at the root.
    2. If key == node: found.
    3. If key < node: go left, else go right.
    4. If you reach NULL: not found.
    Insert(key)
    1. If the tree is empty, the key becomes the root.
    2. Otherwise compare as in search, going left or right.
    3. When the spot you need is NULL, attach the new node there.
    Delete(key): 3 cases
    1. Leaf: just remove it.
    2. One child: link the parent straight to that child.
    3. Two children: replace the key with its inorder successor (smallest key in the right subtree), then delete the successor.

    Worked example: insert 45, 15, 79, 90, 10, 55, 12, 20, 50

    Complexity: search, insert and delete take O(h) where h is the height. That is O(log n) for a balanced tree but O(n) for a skewed one, which is why AVL trees exist.

    Part 4

    Constructing a tree from traversals

    Preorder or postorder tells you who the root is. Inorder tells you who goes left and who goes right.

    Seating a family photo. One list tells you who is the eldest of each group (the root). The other list is the left-to-right order in the photo (inorder): everyone left of the eldest belongs to the left group, everyone right of them to the right group.

    Algorithm (inorder + preorder)
    1. The first element of preorder is the root.
    2. Find the root in the inorder list. Elements to its left form the left subtree, elements to its right form the right subtree.
    3. Take the next element of preorder: it is the root of the left subtree. Repeat steps 2–3 for it.
    4. When the left subtree is done, continue with the right subtree.

    With inorder + postorder the only change: take roots from the end of postorder, and build the right subtree before the left.

    You always need inorder. Preorder + postorder alone can’t tell left from right when a node has only one child, so they don’t give a unique binary tree.

    Part 5

    AVL trees: self-balancing BSTs

    An AVL tree is a BST where, for every node, the heights of the left and right subtrees differ by at most 1.

    A BST built from 10, 20, 30, 40, 50 becomes a straight line (skewed), so searching is as slow as a linked list. An AVL tree is a BST with a rule that keeps it from leaning: whenever one side gets too heavy, it rotates to rebalance, like shifting books so a shelf doesn’t tip over. Named after its inventors Adelson-Velsky and Landis.

    BF(node) = height(left subtree) − height(right subtree). In an AVL tree every BF is −1, 0 or +1. If any BF becomes +2 or −2, rotate.

    The four cases and their rotations

    Find the lowest node that became unbalanced. Look at the path from it towards the newly inserted node: the first two steps name the case.

    CaseNew key went…BF of unbalanced nodeFix
    LLLeft, then Left+2One right rotation
    RRRight, then Right−2One left rotation
    LRLeft, then Right+2Left rotation at the child, then right rotation
    RLRight, then Left−2Right rotation at the child, then left rotation

    Rotate the opposite way to the lean. Leaning left (LL) → rotate right. Leaning right (RR) → rotate left. For a zig-zag (LR or RL), first straighten the zig-zag with a rotation at the child, then do the single rotation.

    LL: insert 30, 20, 10
    RR: insert 10, 20, 30
    LR: insert 30, 10, 20
    RL: insert 10, 30, 20

    The general rotation in words. Right rotation at Z: Z’s left child Y moves up into Z’s place; Z becomes Y’s right child; Y’s old right subtree becomes Z’s new left subtree. Left rotation is the mirror image. Everything stays in BST order.

    AVL insertion algorithm
    1. Insert the key exactly as in a BST.
    2. Walk back up from the new node, updating heights and balance factors.
    3. At the first node whose BF is +2 or −2, identify the case (LL, RR, LR, RL) and apply its rotation.
    4. After one (single or double) rotation, the whole tree is balanced again.

    Worked example: 50, 20, 60, 10, 8, 15, 32, 46, 11, 48

    Deletion works the same way: delete as in a BST, then walk up and rotate wherever a BF becomes ±2 (you may need more than one rotation on the way up). Complexity: search, insert, delete are all O(log n) because the height stays about log₂ n.

    Part 6

    B-trees

    A B-tree is a balanced multi-way search tree: each node can hold several keys and have many children, and all leaves are on the same level.

    A library catalogue. Instead of a yes/no question at each step (binary), each drawer label splits the books into many ranges: A–F, G–M, N–S, T–Z. Fewer steps to reach the right shelf. Databases and file systems use B-trees because reading from disk is slow, and a short, wide tree needs very few disk reads.

    Properties of a B-tree of order m

    1. Every node has at most m children and at most m − 1 keys.
    2. Every internal node except the root has at least ⌈m/2⌉ children (so at least ⌈m/2⌉ − 1 keys).
    3. The root has at least 2 children (unless it is a leaf).
    4. All leaves are on the same level (the tree is always perfectly balanced).
    5. Keys inside a node are in sorted order, and a node with k keys has k + 1 children. Keys in the i-th child lie between the (i−1)-th and i-th keys of the parent.

    Insertion algorithm
    1. Search for the key’s place: start at the root and go down to the correct leaf.
    2. Insert the key into that leaf in sorted order.
    3. If the leaf now has m keys (one too many), split it: the median key moves up into the parent, the keys left of it form one node, the keys right of it form another.
    4. If the parent now overflows, split it the same way. Repeat upwards.
    5. If the root splits, the median becomes a new root and the tree grows one level taller. B-trees grow at the top, never at the bottom.

    Worked example: order 5

    Insert C N G A H E K Q M F W L T Z D P R X Y S into a B-tree of order 5 (max 4 keys per node).

    Deletion in brief

    • Delete from a leaf. If the key is in an internal node, swap it with its inorder predecessor or successor (which is in a leaf) first.
    • If the leaf now has too few keys: borrow a key from a sibling through the parent, if the sibling has a spare.
    • Otherwise merge the leaf with a sibling and pull the separating key down from the parent. This can shrink the tree’s height.

    Leaves are not linkedLeaves are linked, so range queries are fast
    Keys appear onceInternal keys are copies used as signposts

    Applications: database indexes (MySQL, Oracle), file systems (NTFS, ext4), anything stored on disk. Complexity: search, insert and delete are O(log n).

    Two classic mistakes: inserting a new key into an internal node (always insert into a leaf), and forgetting that splitting pushes the median up instead of the new key.

    Part 7

    Hashing and collision resolution

    Hashing uses a hash function to turn a key directly into an array index, so search, insert and delete take O(1) on average.

    Lockers at the gym. Your locker number is your roll number mod 100: roll 2345 → locker 45. You walk straight to it, no searching. But roll 1245 also maps to locker 45. That clash is a collision, and collision resolution is the rule for where the second person goes.

    TermMeaning
    Hash tableThe array that stores the keys. Each position is a slot or bucket.
    Hash function h(k)Turns a key into a slot number between 0 and m − 1.
    CollisionTwo different keys get the same slot.
    Load factor αα = n / m (keys stored ÷ table size). Lower α → fewer collisions.

    Hash functions

    1. Division: h(k) = k mod m. Choose m as a prime. The most common in exams.
    2. Mid-square: square the key and take the middle digits. 123² = 15129 → middle “1” or “51”.
    3. Folding: split the key into parts and add them. 123456 → 123 + 456 = 579.
    4. Multiplication: h(k) = ⌊m × (k·A mod 1)⌋ with 0 < A < 1 (often A ≈ 0.618).

    A good hash function is quick to compute, spreads keys evenly over the table, and causes few collisions.

    Collision resolution techniques

    1. Separate chaining (open hashing)

    Each slot holds a linked list. Colliding keys are added to that slot’s list. The table never “fills up”.

    2. Open addressing (closed hashing)

    All keys live inside the table itself. On a collision, probe other slots until a free one is found:

    • Linear probing: h, h+1, h+2, … → (h + i) mod m
    • Quadratic probing: h, h+1, h+4, h+9, … → (h + i²) mod m
    • Double hashing: (h1(k) + i·h2(k)) mod m, with a second hash such as h2(k) = R − (k mod R)

    Part 8

    Spanning trees

    A spanning tree of a connected graph is a subgraph that includes every vertex, is connected, and has no cycle.

    A town has many possible roads between 4 villages. The council only needs enough roads so that every village can reach every other one, with no road that makes a loop (a loop means one road was unnecessary). That minimal road network is a spanning tree.

    Properties

    • A graph with n vertices has spanning trees with exactly n − 1 edges.
    • It has no cycles. Adding any one more edge creates a cycle.
    • Removing any one edge disconnects it (it is “minimally connected”).
    • A connected graph can have many spanning trees. A disconnected graph has none.
    • A complete graph with n vertices has nn−2 spanning trees (Cayley’s formula). K₄ has 4² = 16.

    In a weighted graph, the MST is the spanning tree whose total edge weight is the smallest. Two famous algorithms find it: Prim’s and Kruskal’s (Q25).

    Applications: designing cable, road, water or electricity networks at minimum cost; network routing protocols (avoiding loops); cluster analysis; approximate solutions to the travelling salesman problem.

    Adjacency matrix and adjacency list

    Two ways to store a graph: a V × V table of 0s and 1s, or one linked list of neighbours per vertex.

    Adjacency matrix

    Adjacency list

    An array of V linked lists. List i holds every neighbour of vertex i. Uses memory only for edges that exist.

    Part 3

    Breadth-first and depth-first search

    BFS visits vertices level by level using a queue. DFS goes as deep as possible using a stack, then backtracks.

    Dropping a stone in a pond. The ripple reaches everything 1 step away, then everything 2 steps away, and so on. Or telling a rumour to all your friends, who each tell all their friends.

    Exploring a maze. Keep walking down one corridor until you hit a dead end, then go back to the last junction and try the next corridor.

    BFS(start) queue
    1. Mark all vertices unvisited.
    2. Mark start as visited and enqueue it.
    3. While the queue is not empty: dequeue a vertex u and print it.
    4. For every neighbour v of u: if v is not visited, mark it visited and enqueue it.
    DFS(u) stack / recursion
    1. Mark u as visited and print it (push u).
    2. For every neighbour v of u: if v is not visited, call DFS(v).
    3. When all neighbours are visited, backtrack (pop u).
    4. Start with DFS(start).

    BFS = Breadth = Queue (think “Big Queue at the bank”). DFS = Depth = Stack (“Dive Down, then Step back”).

    Part 4

    Prim’s algorithm

    Prim’s grows one tree from a starting vertex, each time adding the cheapest edge that connects a new vertex to the tree.

    A cable company starts at its office. Each day it lays the cheapest cable from any connected house to any unconnected house. It never connects two houses that are already connected. When every house is connected, it stops.

    Prim’s algorithm
    1. Pick a start vertex. Put it in the tree. Total cost = 0.
    2. Look at every edge with one end in the tree and the other end outside.
    3. Choose the one with the minimum weight. Add that edge and its new vertex to the tree. Add the weight to the total.
    4. Repeat steps 2–3 until all V vertices are in the tree (you will have V − 1 edges).

    Complexity: O(V²) with an adjacency matrix; O(E log V) with a priority queue (min-heap). Prim’s is a greedy algorithm: it always takes the best-looking choice right now, and for MSTs that is provably correct.

    Part 5

    Kruskal’s algorithm

    Kruskal’s sorts all edges by weight and accepts each one in turn unless it would form a cycle.

    You have a shopping list of every possible road with its cost, sorted cheapest first. Go down the list and build each road, unless both villages are already connected (then that road would only create a loop, so skip it). Stop when you have built V − 1 roads.

    Kruskal’s algorithm
    1. Sort all edges in increasing order of weight.
    2. Start with every vertex in its own set (a forest of single vertices).

    Define a data structure. Explain the classification of data structures with examples.

    Definition

    A data structure is a way of organising and storing data in memory so that it can be accessed and modified efficiently. It defines both how data is arranged and which operations (insert, delete, search, traverse) can be performed on it.

    Classification
    Data Structures ├── Primitive ── int, float, char, double, pointer └── Non-primitive ├── Linear ──── Array, Linked list, Stack, Queue └── Non-linear ─ Tree, Graph
    1. Primitive: basic types provided by the language, holding a single value. Example: int a = 5;
    2. Non-primitive: derived from primitive types, holding many values.
      • Linear: elements are arranged in a sequence; each has a unique predecessor and successor. Examples: array, linked list, stack, queue.
      • Non-linear: elements are arranged in a hierarchy or network. Examples: tree (hierarchy), graph (network).
    Other ways to classify
    • Static vs dynamic: size fixed at compile time (array) vs size changes at run time (linked list).
    • Homogeneous vs heterogeneous: same type of elements (array) vs different types (structure).
    Operations on data structures

    Traversing, searching, insertion, deletion, sorting and merging.

    Abstract Data Type

    An ADT specifies the data and the operations without the implementation. Example: Stack ADT = {push, pop, peek, isEmpty}, implementable with an array or a linked list.

    Need for data structures

    Efficient use of memory, faster search and update, easier handling of large data, and reusability.

    Conclusion

    Choosing the right data structure decides how fast and how memory-efficient a program is.

    Define time and space complexity. Explain asymptotic notations with examples.

    Definitions

    Time complexity is the amount of time an algorithm takes, expressed as the number of basic steps as a function of the input size n. Space complexity is the total memory it needs as a function of n: a fixed part (code, constants, simple variables) plus a variable part (arrays, recursion stack).

    Best, average and worst case (linear search)
    • Best: key at first position → 1 comparison → Ω(1).
    • Average: about n/2 comparisons → Θ(n).
    • Worst: key last or absent → n comparisons → O(n).
    Asymptotic notations
    1. Big-O (upper bound): f(n) = O(g(n)) if there exist positive constants c and n₀ such that 0 ≤ f(n) ≤ c·g(n) for all n ≥ n₀. Describes the worst case. Example: 3n + 2 = O(n) (take c = 4, n₀ = 2).
    2. Omega (lower bound): f(n) = Ω(g(n)) if f(n) ≥ c·g(n) for all n ≥ n₀. Describes the best case. Example: 3n + 2 = Ω(n) (c = 3).
    3. Theta (tight bound): f(n) = Θ(g(n)) if c₁·g(n) ≤ f(n) ≤ c₂·g(n) for all n ≥ n₀. Example: 3n + 2 = Θ(n).
    Common complexities

    O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)

    Example of analysis
    for i = 1 to n → runs n times for j = 1 to n → runs n times for each i sum = sum + 1 → total n × n = n² ⇒ O(n²)

    Linear search: O(n). Binary search: O(log n). Bubble sort: O(n²).

    Space complexity example

    Summing an array of n elements needs the array (n words) plus a few variables: S(n) = n + 3 → O(n).

    Conclusion

    Asymptotic analysis compares algorithms independent of the machine, by how they grow for large n.

    Stacks and queues

    What is a stack? Explain the push and pop operations using an array, with overflow and underflow conditions. List its applications.

    Definition

    A stack is a linear data structure in which insertion and deletion take place at only one end, called the top. It follows LIFO (Last In, First Out). Example: a pile of plates.

    Operations

    push(x) inserts at top, pop() removes from top, peek() returns the top, isEmpty(), isFull(). All are O(1).

    Array implementation (stack[MAX], top = −1 initially)

    PUSH(x)

    1. If top == MAX − 1: print “Stack Overflow”, stop.
    2. top = top + 1.
    3. stack[top] = x.

    POP()

    1. If top == −1: print “Stack Underflow”, stop.
    2. x = stack[top].
    3. top = top − 1; return x.
    Overflow and underflow
    • Overflow: push on a full stack (top == MAX − 1).
    • Underflow: pop on an empty stack (top == −1).
    Example

    push(10), push(20), push(30) → stack = [10, 20, 30], top = 2. pop() returns 30 → top = 1.

    Linked list implementation

    push = insert at beginning, pop = delete from beginning; head acts as top. No overflow until memory runs out.

    Applications

    Function calls and recursion, undo, browser back, balanced parentheses, infix to postfix conversion, postfix evaluation, reversing data, backtracking.

    What is a queue? What is the drawback of a linear queue? Explain a circular queue with insertion and deletion algorithms and an example.

    Queue

    A queue is a linear data structure where insertion happens at the rear and deletion at the front. It follows FIFO (First In, First Out). Example: a ticket counter line.

    Drawback of a linear queue

    In an array queue, rear only moves forward. After some deletions, the slots at the front become empty, but when rear == MAX − 1 the queue reports overflow even though space is free. That space is wasted.

    front = 2, rear = 4: “full”, yet slots 0 and 1 are empty.

    Circular queue

    A circular queue connects the last position back to the first, using (index + 1) % SIZE, so empty slots are reused. Full: (rear + 1) % SIZE == front. Empty: front == −1.

    ENQUEUE(x)

    1. If (rear + 1) % SIZE == front: “Overflow”, stop.
    2. If front == −1: front = rear = 0; else rear = (rear + 1) % SIZE.
    3. queue[rear] = x.

    DEQUEUE()

    1. If front == −1: “Underflow”, stop.
    2. x = queue[front].
    3. If front == rear: front = rear = −1; else front = (front + 1) % SIZE.
    4. Return x.
    Example (SIZE = 5)
    Advantages

    No wasted space, efficient use of a fixed array, all operations O(1).

    Applications

    CPU round-robin scheduling, traffic signal systems, keyboard and streaming buffers, printer spooling.

    Write an algorithm to check whether the parentheses in an expression are balanced using a stack. Trace it for {[()]} and ([)].

    Idea

    The last bracket opened must be the first one closed. This is LIFO, so a stack is used.

    Algorithm
    1. Initialise an empty stack.
    2. Scan the expression from left to right.
    3. If the symbol is an opening bracket (, [ or {, push it.
    4. If it is a closing bracket: if the stack is empty → not balanced; else pop, and if the popped bracket does not match → not balanced.
    5. After the scan: stack empty → balanced; otherwise → not balanced.
    Trace 1: {[()]}
    Trace 2: ([)]
    Cases of imbalance
    • Mismatched type: ([)]
    • Extra closing bracket: a+b)
    • Unclosed opening bracket: ((a+b)
    Complexity

    O(n) time, O(n) space for the stack in the worst case. Used by compilers to check syntax.

    Write an algorithm to convert an infix expression to postfix using a stack. Convert A + B * (C ^ D − E) ^ (F + G * H) − I.

    Notations

    Infix: operator between operands (A + B). Prefix: operator before (+ A B). Postfix: operator after (A B +). Postfix needs no brackets and no precedence rules to evaluate, so computers prefer it.

    Precedence

    ^ (highest, right to left) > * / % (left to right) > + − (lowest, left to right).

    Algorithm
    1. Scan the infix expression from left to right.
    2. If the symbol is an operand, add it to postfix.
    3. If it is (, push it onto the stack.
    4. If it is ), pop and add to postfix until ( is found; discard both brackets.
    5. If it is an operator: while the stack top is an operator of higher precedence (or equal precedence and the scanned operator is left-associative), pop it to postfix. Then push the scanned operator.
    6. At the end, pop all remaining operators to postfix.
    Conversion table
    Evaluating a postfix expression
    1. Scan left to right.
    2. Operand → push.
    3. Operator → pop B, pop A, push A op B.
    4. The final value on the stack is the result.

    Define a tree. Explain tree terminology, types of binary trees and their representation.

    Definition

    A tree is a non-linear, hierarchical data structure consisting of nodes connected by edges, with one special node called the root; the remaining nodes form disjoint subtrees. A tree with n nodes has n − 1 edges and no cycles.

    Terminology (for the tree above)
    • Root: 50. Leaves: 20, 40, 60, 80. Internal nodes: 50, 30, 70.
    • Parent/child: 30 is the parent of 20 and 40. Siblings: 20 and 40.
    • Degree of a node: number of children (degree of 30 = 2).
    • Level/depth: edges from the root (50 at level 0, 30 at level 1). Height of the tree: 2.
    • Ancestors of 40: 30, 50. Subtree: a node with all its descendants.
    Binary tree and its types

    A binary tree is a tree in which every node has at most two children (left and right).

    • Full/strict: every node has 0 or 2 children.
    • Complete: all levels full except the last, filled from the left.
    • Perfect: all internal nodes have 2 children and all leaves are at the same level.
    • Skewed: every node has only a left (or only a right) child.
    Properties

    Maximum nodes at level i = 2i; maximum nodes in a tree of height h = 2h+1 − 1; minimum height with n nodes = ⌈log₂(n+1)⌉ − 1.

    Representation

    Array: root at index 0; children of i at 2i + 1 and 2i + 2; parent at ⌊(i − 1)/2⌋. Efficient for complete trees.

    Linked: each node is a structure [left | data | right]; NULL for a missing child. Works for any shape.

    Applications

    File systems, organisation charts, expression trees, searching (BST), databases (B-trees).

    What is an AVL tree? Explain the rotations. Construct an AVL tree for 10, 20, 30, 25, 28, 27.

    Definition

    An AVL tree is a height-balanced binary search tree in which the balance factor of every node is −1, 0 or +1, where BF = height(left subtree) − height(right subtree). If an insertion makes any BF ±2, the tree is rebalanced by rotations.

    Rotations
    • LL (inserted in the left subtree of the left child): single right rotation.
    • RR (right subtree of the right child): single left rotation.
    • LR (right subtree of the left child): left rotation at the child, then right rotation.
    • RL (left subtree of the right child): right rotation at the child, then left rotation.

    RR → left rotation

    Height stays O(log n), so search, insert and delete are always O(log n), unlike a skewed BST.

    What is a B-tree? State its properties and construct a B-tree of order 3 by inserting 10, 20, 30, 40, 50, 60, 70, 80, 90.

    Definition

    A B-tree of order m is a balanced multi-way search tree in which each node can contain several keys and children, and all leaves are at the same level. It is used for data stored on disk.

    Properties
    1. Each node has at most m children and at most m − 1 keys.
    2. Each internal node except the root has at least ⌈m/2⌉ children.
    3. The root has at least 2 children if it is not a leaf.
    4. All leaves are at the same level.
    5. Keys in each node are sorted; a node with k keys has k + 1 children.
    Insertion

    Insert into the correct leaf in sorted order. If the node overflows (m keys), split it: the median key moves up to the parent and the rest form two nodes. Splits may propagate up to the root, creating a new root.

    Construction (order 3: max 2 keys per node)
    Applications

    Database indexing and file systems: a short, wide tree means very few disk reads. Search, insert and delete are O(log n).

    What is hashing? Explain hash functions and collision resolution techniques with an example.

    Definition

    Hashing is a technique that maps a key directly to a position in a hash table using a hash function h(k), so that search, insertion and deletion take O(1) time on average.

    Hash functions
    • Division: h(k) = k mod m (m prime). 72 mod 10 = 2.
    • Mid-square: square k and take the middle digits.
    • Folding: split k into parts and add them (123456 → 123 + 456 = 579).
    • Multiplication: h(k) = ⌊m(kA mod 1)⌋, 0 < A < 1.
    Collision

    A collision occurs when two keys hash to the same index (72 and 92 both give 2 for m = 10).

    Collision resolution techniques
    1. Separate chaining (open hashing): each slot stores a linked list of all keys that hash to it.
    2. Open addressing (closed hashing): find another empty slot by probing:
      • Linear probing: (h(k) + i) mod m
      • Quadratic probing: (h(k) + i²) mod m
      • Double hashing: (h1(k) + i·h2(k)) mod m
    Example: 72, 27, 36, 24, 63, 81, 92, 101 with m = 10, linear probing
    Same keys with chaining
    Load factor and clustering

    Load factor α = n/m (here 8/10 = 0.8). Linear probing suffers primary clustering; quadratic probing reduces it but has secondary clustering; double hashing avoids both. When α grows too high, rehash into a larger table.

    What is a spanning tree? What is a minimum spanning tree? State the properties and applications.

    Definition

    A spanning tree of a connected undirected graph G is a subgraph that includes all the vertices of G, is connected, and contains no cycle. It has exactly n − 1 edges for n vertices.

    Properties
    • Contains all n vertices and exactly n − 1 edges.
    • Has no cycles; adding one edge creates a cycle.
    • Removing one edge disconnects it (minimally connected).
    • A connected graph can have many spanning trees; a complete graph Kₙ has nn−2 (Cayley’s formula).
    Minimum spanning tree

    For a weighted graph, the MST is the spanning tree with the minimum total edge weight. It is found using Prim’s or Kruskal’s algorithm.

    Applications

    Designing networks (cable, telephone, electrical, roads) at minimum cost, network routing without loops, clustering, approximating the travelling salesman problem.

    Explain BFS and DFS graph traversals with algorithms and an example. Compare them.

    Breadth-first search (BFS)

    BFS visits all vertices level by level, visiting all neighbours of a vertex before going deeper. It uses a queue.

    1. Mark start as visited and enqueue it.
    2. While the queue is not empty: dequeue u and print it.
    3. For each unvisited neighbour v of u: mark v visited and enqueue it.
    Depth-first search (DFS)

    DFS goes as deep as possible along a path before backtracking. It uses a stack (or recursion).

    1. DFS(u): mark u visited and print it.
    2. For each unvisited neighbour v of u: call DFS(v).
    3. When no unvisited neighbour is left, backtrack.

    Explain Prim’s algorithm to find a minimum spanning tree with an example.

    Introduction

    A minimum spanning tree connects all vertices with the minimum total weight. Prim’s algorithm is a greedy algorithm that grows the MST from a starting vertex, one edge at a time.

    Algorithm
    1. Select any vertex as the start and include it in the MST.
    2. Among all edges with one end in the MST and the other outside, choose the edge of minimum weight.
    3. Add the edge and its new vertex to the MST.
    4. Repeat until all V vertices are included (V − 1 edges).
    Example

    MST edges: A–C (2), C–B (1), B–D (5), D–E (3), D–F (6). Minimum cost = 17.

    Complexity

    O(V²) using an adjacency matrix; O(E log V) using a min-heap. Suitable for dense graphs.

    Explain Kruskal’s algorithm with an example. Compare Prim’s and Kruskal’s algorithms.

    Introduction

    Kruskal’s algorithm is a greedy algorithm that builds the MST by adding edges in increasing order of weight, skipping any edge that would form a cycle.

    Algorithm
    1. Sort all edges in increasing order of weight.
    2. Make each vertex a separate set.
    3. For each edge (u, v) in sorted order: if u and v are in different sets, include the edge and merge the sets (union); otherwise reject it (cycle).
    4. Stop when V − 1 edges have been included.
    Example (same graph)

    Accepted: B–C (1), A–C (2), D–E (3), B–D (5), D–F (6). Rejected: A–B (4), forms the cycle A–B–C. Minimum cost = 17.

    Explain B-trees. Construct a B-tree of order 5 by inserting C N G A H E K Q M F W L T Z D P R X Y S.

    1. Definition

    A B-tree of order m is a balanced m-way search tree used for disk-based storage, in which all leaves are on the same level and each node stores multiple sorted keys.

    2. Properties (order 5)
    • Maximum 5 children and 4 keys per node.
    • Minimum ⌈5/2⌉ = 3 children (2 keys) for internal non-root nodes.
    • Root has at least 2 children unless it is a leaf.
    • All leaves at the same level; keys sorted within nodes.
    3. Insertion procedure

    Insert into the proper leaf. When a node reaches 5 keys, split it: the median (3rd key) moves up, and the remaining keys form two nodes of 2 keys each. Splits can propagate to the root.

    4. Construction

    Final B-tree: root [M]; level 1: [D G] [Q T]; leaves: [A C] [E F] [H K L] [N P] [R S] [W X Y Z].

    5. Deletion

    Delete from a leaf (swap with predecessor/successor if the key is internal). If a node underflows, borrow from a sibling through the parent, or merge with a sibling.

    6. B-tree vs B+ tree

    B+ trees keep all data in linked leaves, making range queries faster; internal nodes only guide the search.

    7. Applications

    Database indexes and file systems; O(log n) search, insert and delete with few disk accesses.
