Cheat sheet

Q21 · Basics

  • Data structure: organises data for efficient access. Linear (array, list, stack, queue) vs non-linear (tree, graph).
  • Structure: groups different types. s.x for a variable, p->x for a pointer.
  • Union: members share memory; size = largest member.
  • malloc(bytes): garbage values · calloc(n, size): zeros · realloc: resize · free: release.
  • Leak = never freed · Dangling = used after free.
  • O upper / worst · Ω lower / best · Θ tight.
  • Single loop O(n) · nested O(n²) · halving O(log n).

Q22 · Linked lists

  • Node = [data | next]; head → first; last → NULL.
  • Insert front: new→next = head; head = new.
  • Insert end: walk to last; last→next = new.
  • Delete front: temp = head; head = head→next; free(temp).
  • Position k: stop at node k − 1, then relink.
  • DLL: [prev | data | next]; update both links.
  • CLL: last→next = head; stop when temp == head.

Q23 · Stacks and queues

  • Stack LIFO; top = −1 empty; top = MAX − 1 full.
  • Queue FIFO; enqueue at rear, dequeue at front.
  • Circular: rear = (rear + 1) % N; full when (rear + 1) % N == front; empty when front == −1.
  • Brackets: push openers; closer must match the top; stack empty at the end.
  • Infix → postfix: operand out; ( push; ) pop until (; operator pops ≥ precedence then pushes. ^ is right-associative.
  • Evaluate postfix: number push; operator pop B, pop A, push A op B.

Q24 · Trees and hashing

  • n nodes → n − 1 edges. Pre: Root L R · In: L Root R · Post: L R Root.
  • BST: left < node < right. Delete with 2 children → inorder successor.
  • Build from traversals: root = first of pre / last of post; split inorder.
  • AVL: BF = h(L) − h(R) ∈ {−1, 0, 1}. LL→right, RR→left, LR→left+right, RL→right+left.
  • B-tree order m: ≤ m − 1 keys; split → median goes up; leaves on one level.
  • Hashing: k mod m. Chaining, linear h+i, quadratic h+i², double h1 + i·h2.
  • Spanning tree: all vertices, n − 1 edges, no cycle. Kₙ has nn−2.

Q25 · Graphs

  • G = (V, E). Matrix O(V²), O(1) edge check. List O(V + E), best for sparse graphs.
  • BFS: queue, level by level, shortest path in unweighted graphs.
  • DFS: stack/recursion, deep then backtrack.
  • Both O(V + E) with lists.
  • Prim: grow one tree from a vertex with the cheapest edge out. O(V²).
  • Kruskal: sort edges; take the cheapest that doesn’t form a cycle (union-find). O(E log E).

Examiners look for these

Mistakes that cost marks

  • Moving head before linking the new node: the list is lost.
  • Forgetting the empty-list (underflow) and single-node cases.
  • Not calling free() after deleting a node.
  • Checking temp == NULL in a circular list: an infinite loop.
  • Updating only next and forgetting prev in a doubly linked list.
  • Circular queue full test written as rear == SIZE − 1.
  • Treating ^ as left-associative: A^B^C is ABC^^, not AB^C^.
  • Writing brackets into the postfix output.
  • Postfix evaluation computing B op A instead of A op B.
  • BST: putting equal or larger keys on the left.
  • AVL: rotating at the wrong node. Fix the lowest node with BF ±2.
  • AVL: naming the case from the root instead of from the unbalanced node.
  • B-tree: splitting too early (before the node has m keys) or sending the wrong key up.
  • Hashing: forgetting “mod m” when probing past the end of the table.
  • Kruskal: accepting an edge that closes a cycle.
  • Prim: picking the cheapest edge in the whole graph (that is Kruskal).
  • BFS/DFS: not marking vertices visited, so they are visited twice.
  • Writing only “Stack” for a scenario, with no reason and no rejected alternative.
  • O(2n) or O(n² + n) left unsimplified: write O(n) and O(n²).
  • No diagram. Almost every DSA answer needs one.

Exam morning checklist

  • Read the whole paper first; start with the question you know best.
  • Split your time by marks: about 15 minutes for each 8-mark answer, 30 for each 15-mark answer.
  • Every answer: definition, diagram, steps, example, complexity, applications.
  • For “write a program”: if you can’t remember the code, write the algorithm in numbered steps. That still earns most of the marks.
  • For tracing questions (AVL, B-tree, hashing, Prim, Kruskal, infix): show every step in a table. The steps carry the marks.
  • Scenario: operations → data structure → why + complexity → why not the other.
  • Leave 5 minutes to underline keywords and label diagrams.

You’ve got this. You don’t have to remember everything. Clear headings, a neat diagram and a worked example will carry you through every question on this paper.
