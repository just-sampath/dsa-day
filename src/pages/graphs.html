Graphs: BFS, DFS, Prim and Kruskal

A graph is a set of points joined by lines: cities and roads, people and friendships, web pages and links. You’ll store graphs two ways, walk through them breadth-first and depth-first, and find the cheapest way to connect everything.

Part 1

What is a graph?

A graph G = (V, E) is a set of vertices V (nodes) and a set of edges E that connect pairs of vertices.

A map of cities. Cities are vertices, roads are edges. A one-way street is a directed edge. The road’s length in km is a weight. Unlike a tree, a graph can have loops of roads (cycles) and no single “root”.

TermMeaning
Undirected graphEdges have no direction: A–B is the same as B–A.
Directed graph (digraph)Edges have a direction: A → B does not mean B → A.
Weighted graphEach edge carries a number (cost, distance, time).
AdjacentTwo vertices joined by an edge are neighbours.
DegreeNumber of edges at a vertex. In a digraph: in-degree (edges coming in) and out-degree (edges going out).
PathA sequence of vertices joined by edges.
CycleA path that starts and ends at the same vertex.
ConnectedThere is a path between every pair of vertices.
Complete graph KₙEvery vertex is joined to every other: n(n − 1)/2 edges.
DAGDirected Acyclic Graph: directed, with no cycles (used for task scheduling).

Handshake rule: in any undirected graph, the sum of all degrees = 2 × number of edges, because every edge touches two vertices.

Part 2

Adjacency matrix and adjacency list

Two ways to store a graph: a V × V table of 0s and 1s, or one linked list of neighbours per vertex.

Adjacency matrix

A 2-D array M[V][V]. M[i][j] = 1 if there is an edge from i to j, otherwise 0. For a weighted graph, store the weight instead of 1. For an undirected graph the matrix is symmetric.

Adjacency list

An array of V linked lists. List i holds every neighbour of vertex i. Uses memory only for edges that exist.

Adjacency matrixAdjacency list
MemoryO(V²)O(V + E)

For an undirected graph, every edge appears twice: M[u][v] and M[v][u] in the matrix, and in both u’s and v’s lists. Forgetting the second copy is the most common error.

Part 3

Breadth-first and depth-first search

BFS visits vertices level by level using a queue. DFS goes as deep as possible using a stack, then backtracks.

Dropping a stone in a pond. The ripple reaches everything 1 step away, then everything 2 steps away, and so on. Or telling a rumour to all your friends, who each tell all their friends.

Exploring a maze. Keep walking down one corridor until you hit a dead end, then go back to the last junction and try the next corridor.

BFS(start) queue
  1. Mark all vertices unvisited.
  2. Mark start as visited and enqueue it.
  3. While the queue is not empty: dequeue a vertex u and print it.
  4. For every neighbour v of u: if v is not visited, mark it visited and enqueue it.
DFS(u) stack / recursion
  1. Mark u as visited and print it (push u).
  2. For every neighbour v of u: if v is not visited, call DFS(v).
  3. When all neighbours are visited, backtrack (pop u).
  4. Start with DFS(start).

BFS = Breadth = Queue (think “Big Queue at the bank”). DFS = Depth = Stack (“Dive Down, then Step back”).

The order depends on the order you take neighbours. Always say “neighbours are visited in alphabetical (or numerical) order” in your answer. Also mark a vertex visited when you enqueue it in BFS, not when you dequeue it, or it may be added twice.

Part 4

Prim’s algorithm

Prim’s grows one tree from a starting vertex, each time adding the cheapest edge that connects a new vertex to the tree.

A cable company starts at its office. Each day it lays the cheapest cable from any connected house to any unconnected house. It never connects two houses that are already connected. When every house is connected, it stops.

Prim’s algorithm
  1. Pick a start vertex. Put it in the tree. Total cost = 0.
  2. Look at every edge with one end in the tree and the other end outside.
  3. Choose the one with the minimum weight. Add that edge and its new vertex to the tree. Add the weight to the total.
  4. Repeat steps 2–3 until all V vertices are in the tree (you will have V − 1 edges).

Complexity: O(V²) with an adjacency matrix; O(E log V) with a priority queue (min-heap). Prim’s is a greedy algorithm: it always takes the best-looking choice right now, and for MSTs that is provably correct.

Part 5

Kruskal’s algorithm

Kruskal’s sorts all edges by weight and accepts each one in turn unless it would form a cycle.

You have a shopping list of every possible road with its cost, sorted cheapest first. Go down the list and build each road, unless both villages are already connected (then that road would only create a loop, so skip it). Stop when you have built V − 1 roads.

Kruskal’s algorithm
  1. Sort all edges in increasing order of weight.
  2. Start with every vertex in its own set (a forest of single vertices).
  3. Take the next cheapest edge (u, v). If u and v are in different sets, accept it and union (merge) the two sets. If they are in the same set, reject it: it would form a cycle.
  4. Stop when V − 1 edges are accepted.

Union-find is how we check for a cycle quickly: keep groups of connected vertices. Same group = already connected = cycle. You don’t need to code it: in the exam, just write the sets after each step, like the table below.

Prim vs Kruskal

Prim’sKruskal’s
Starts from a vertexStarts from the sorted list of edges
Always one connected tree while it worksA forest of pieces that slowly join together
Picks the cheapest edge leaving the treePicks the cheapest edge overall that makes no cycle
Better for dense graphsBetter for sparse graphs
O(V²) or O(E log V)O(E log E)
Both are greedy and both give the same minimum total cost.

In Kruskal’s, rejecting an edge is a step you must show, with the reason “forms a cycle”. In Prim’s, never pick an edge whose two ends are already both in the tree.
