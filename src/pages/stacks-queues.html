Stacks and queues

Two simple rules run half of computing. A stack serves the newest item first (LIFO). A queue serves the oldest item first (FIFO). Then we use a stack to check brackets and to convert expressions, the most predictable question in the paper.

Part 1

Stack: Last In, First Out

A stack is a linear data structure where insertion and deletion happen at one end only, called the top. Last In, First Out (LIFO).

A stack of plates in the canteen. You put a clean plate on top, and you take a plate from the top. The plate you put last is the first one taken. You never pull a plate from the middle.

Operations

OperationWhat it doesTime
push(x)Put x on topO(1)
pop()Remove and return the top itemO(1)
peek() / top()Look at the top item without removing itO(1)
isEmpty()True when top == −1O(1)
isFull()True when top == MAX − 1 (array version)O(1)

Array implementation

Use an array stack[MAX] and a variable top that holds the index of the top item. An empty stack has top = −1.

PUSH(x)
  1. If top == MAX − 1: print “Stack Overflow”, stop.
  2. top = top + 1.
  3. stack[top] = x.
POP()
  1. If top == −1: print “Stack Underflow”, stop.
  2. x = stack[top].
  3. top = top − 1.
  4. Return x.

Trying to push into a full stack. Condition: top == MAX − 1.

Trying to pop from an empty stack. Condition: top == −1.

Linked list implementation

Push = insert at beginning, pop = delete from beginning of a singly linked list (Q22). The head pointer acts as top. Both are O(1), and the stack never overflows until the computer runs out of memory.

Applications of stacks

  • Function calls and recursion (the call stack)
  • Undo in editors
  • Browser back button
  • Balanced parentheses checking
  • Infix to postfix/prefix conversion
  • Evaluating postfix expressions
  • Reversing a word or a list
  • Backtracking (maze, DFS in Q25)

Part 2

Queue: First In, First Out

A queue inserts at one end (the rear) and deletes from the other end (the front). First In, First Out (FIFO).

The canteen line. New people join at the back (rear). The person at the front is served and leaves. Whoever came first is served first. No cutting in.

OperationWhat it doesCondition to check
enqueue(x)Add x at the rearOverflow if rear == MAX − 1
dequeue()Remove the item at the frontUnderflow if front == −1 or front > rear
peek()Look at the front itemQueue must not be empty
ENQUEUE(x), linear
  1. If rear == MAX − 1: “Queue Overflow”, stop.
  2. If front == −1: front = 0.
  3. rear = rear + 1; queue[rear] = x.
DEQUEUE(), linear
  1. If front == −1 or front > rear: “Queue Underflow”, stop.
  2. x = queue[front].
  3. front = front + 1. Return x.

The big drawback of a linear queue

Once rear reaches the end of the array, the queue says “full” even if you have already dequeued items and the slots at the front are empty. Those slots are wasted forever. Try it: enqueue 5 items, dequeue 2, then enqueue again.

Applications of queues

  • Printer job queue (print spooler)
  • CPU scheduling (first come, first served)
  • Breadth-first search in graphs (Q25)
  • Call-centre and ticket-counter waiting lines
  • Keyboard buffer
  • Sending data packets over a network

Part 3

Circular queue

In a circular queue, the last position is connected back to the first, so rear wraps around and reuses the empty slots at the front.

A round table with 5 chairs. When the last chair is taken, the next guest sits in chair 0 if it has been freed. The trick that makes this work in an array is the modulo operator: (rear + 1) % SIZE goes 0, 1, 2, 3, 4, 0, 1, …

(rear + 1) % SIZE == front

front == −1

ENQUEUE(x)
  1. If (rear + 1) % SIZE == front: “Queue Overflow”, stop.
  2. If front == −1: front = rear = 0.
  3. Else: rear = (rear + 1) % SIZE.
  4. queue[rear] = x.
DEQUEUE()
  1. If front == −1: “Queue Underflow”, stop.
  2. x = queue[front].
  3. If front == rear (only one item): front = rear = −1.
  4. Else: front = (front + 1) % SIZE.
  5. Return x.

Worked trace (SIZE = 5)

Write a table like this in the exam. Watch rear wrap from 4 to 0.

Linear queueCircular queue
Rear only moves forwardRear wraps around with % SIZE
Freed front slots are wastedFreed slots are reused
Full when rear == MAX − 1Full when (rear + 1) % SIZE == front

Two relatives you may be asked to define: a deque (double-ended queue) allows insert and delete at both ends; a priority queue serves the item with the highest priority first, not the oldest.

Part 4

Balanced parentheses using a stack

An expression is balanced when every opening bracket has a matching closing bracket of the same type, in the right order.

Russian nesting dolls. The last doll you opened must be the first one you close. That “last opened, first closed” rule is exactly LIFO, so a stack is the perfect tool.

Algorithm
  1. Create an empty stack.
  2. Scan the expression from left to right, one character at a time.
  3. If it is an opening bracket ( [ {: push it.
  4. If it is a closing bracket ) ] }: if the stack is empty → not balanced. Otherwise pop; if the popped bracket is not the matching type → not balanced.
  5. Ignore every other character.
  6. At the end: if the stack is empty → balanced, otherwise → not balanced.

Traces to copy into your answer

There are three ways to fail, and a full answer mentions all three: a wrong type (([)]), an extra closing bracket (a+b)), and an unclosed bracket left on the stack (((a+b)).

Part 5

Infix to postfix conversion

Postfix puts each operator after its two operands, so the computer never needs brackets or precedence rules to evaluate it.

NotationOperator positionExample
InfixBetween operands (how we write)A + B
Prefix (Polish)Before operands+ A B
Postfix (Reverse Polish)After operandsA B +

An old calculator that wants numbers first, then the button: “5, 3, plus”. Postfix is that order. Because the operator always comes after what it works on, there is never any confusion about what to do first.

Precedence and associativity

OperatorPrecedenceAssociativity
^Highest (3)Right to left: A^B^C = A^(B^C)
* / %Middle (2)Left to right
+ −Lowest (1)Left to right
Algorithm: infix → postfix using a stack
  1. Scan the infix expression from left to right.
  2. If the symbol is an operand (A, B, 5…): write it to the postfix output.
  3. If it is (: push it.
  4. If it is ): pop and output everything until (, then throw both brackets away.
  5. If it is an operator: while the top of the stack is an operator with higher precedence, or equal precedence and the incoming operator is left-associative, pop it to the output. Then push the incoming operator.
  6. At the end, pop everything left on the stack to the output.

“Operands walk straight through, operators wait on the stack.” An operator is only allowed to sit on top of a weaker operator. If a stronger (or equal) one is on top, kick it out to the output first. Exception: ^ can sit on another ^.

Worked examples

Example 1: A + B * C
Example 2: (A + B) * (C − D)
Example 3 (classic exam question): A + B * (C ^ D − E) ^ (F + G * H) − I

Infix to prefix (the reverse trick)

Reverse the infix (swap ( and )), convert to postfix, reverse the answer.

Two common slips: popping ^ when another ^ arrives (it is right-associative, so push), and forgetting to empty the stack at the end. Also, brackets never appear in a postfix answer.

Part 6

Evaluating a postfix expression

Push numbers. When an operator comes, pop two, compute, push the result.

Algorithm
  1. Scan the postfix expression left to right.
  2. Operand → push it.
  3. Operator → pop B (the top), then pop A. Compute A op B and push the result.
  4. At the end, the single value on the stack is the answer.

The order matters for − and /. The first value you pop is the right operand. For 8 2 −: pop 2 (B), pop 8 (A), compute 8 − 2 = 6, not 2 − 8.
