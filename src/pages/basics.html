Part 1

What is a data structure?

A data structure is a way of organising data in memory so it can be used efficiently.

Think of your wardrobe. You could throw every piece of clothing in one pile, and you’d still own the same clothes. But with shelves, hangers and drawers you find your jeans in two seconds. A data structure is the shelving for data. An algorithm is the step-by-step recipe you follow to use it (find, add, remove, sort).

Programs store marks, names, bus routes, friend lists. How you store them decides how fast you can search, insert and delete. That’s the whole subject: pick the right shelf for the job.

Abstract Data Type (ADT)

An ADT describes what a data structure does (its operations) without saying how it is built. For example, the Stack ADT promises push, pop, peek and isEmpty. You can build it with an array or with a linked list. The user doesn’t care which.

Algorithm and its 5 properties

An algorithm is a finite set of clear steps that solves a problem. Every algorithm must have:

  1. Input: zero or more values given to it.
  2. Output: at least one result.
  3. Definiteness: every step is clear and unambiguous.
  4. Finiteness: it stops after a finite number of steps.
  5. Effectiveness: every step is basic enough to actually carry out.

“I O D F E”: Input, Output, Definiteness, Finiteness, Effectiveness. Say it as “I Owe Dad Five Euros”.

Common operations on any data structure: traversal (visit each element), insertion, deletion, searching, sorting, merging.

Part 2

Structures (struct)

A structure groups different types of data under one name.

Your college ID card has your roll number (a number), your name (text) and your CGPA (a decimal). They are different kinds of data, but they all describe one student. A structure is that ID card: one name, many fields.

An array can only hold items of the same type (50 marks, all int). A structure can hold items of different types. Each item inside it is called a member (or field).

3. Array of structures

For a whole class you don’t make 60 separate variables. You make an array of structures: struct student cls[60]; Then cls[0].roll is the first student’s roll number, cls[1].name the second student’s name, and so on.

4. Pointer to a structure: the arrow operator

A pointer is a variable that stores an address (where something lives in memory). When you have a pointer to a structure, you reach its members with the arrow -> instead of the dot.

Dot for the thing, arrow for the pointer. s1.marks when you hold the structure itself, p->marks when you hold its address. Linked lists use -> everywhere, so this matters for Q22 too.

5. Nested structures and typedef

  • Nested structure: a structure inside another. A student can contain a struct date dob; and you reach it with s1.dob.year.
  • typedef gives a type a short nickname: typedef struct student Student; lets you write Student s1; instead of struct student s1;.

Part 3

Dynamic memory allocation (DMA)

Dynamic memory allocation means getting memory while the program is running, exactly as much as you need.

A static array is like booking a hall for 100 guests months in advance: if 30 come, 70 chairs are wasted; if 120 come, you’re stuck. Dynamic allocation is like ordering chairs on the day of the party, once you know the exact headcount, and returning them afterwards.

The four functions live in <stdlib.h>. Each one hands back a pointer (an address) to the memory it reserved, or NULL if there wasn’t enough.

malloc: “memory allocate”

ptr = (int *) malloc(n * sizeof(int));

Reserves one block of n × 4 bytes. The values inside are garbage (random leftovers).

calloc: “contiguous allocate”

ptr = (int *) calloc(n, sizeof(int));

Takes two arguments (how many, size of each) and sets every byte to zero.

realloc: “re-allocate”

ptr = (int *) realloc(ptr, newSize);

Changes the size of a block you already have. Old values are kept.

free

free(ptr); ptr = NULL;

Gives the memory back to the heap. Setting the pointer to NULL afterwards is good practice.

Reading the malloc line: sizeof(int) asks “how many bytes is one int?” (4). Multiply by n to get the total. (int *) tells C to treat the block as ints. Then always check: if (ptr == NULL) { printf("No memory"); }

Two classic bugs

You allocate memory but never free it, and then lose its address (for example, by pointing the pointer somewhere else). The memory stays reserved until the program ends.

You free the memory but keep using the old pointer. It “dangles”, pointing at memory that isn’t yours. Fix: set it to NULL after free.

Example: marks of n students

Algorithm in plain English
  1. Read n, the number of students.
  2. Ask for memory for n integers using malloc. If it returns NULL, print “no memory” and stop.
  3. Read the n marks into that memory.
  4. Print them (or compute the average).
  5. free the memory and set the pointer to NULL.

Part 4

Time and space complexity

Complexity tells you how the work grows as the input grows.

Finding a friend’s name in a class register: if you read every name from the top, 60 students means up to 60 checks, 600 means up to 600. The work grows in step with the size: that’s O(n). If the register is sorted and you open it in the middle and keep halving, 600 names need only about 10 checks: that’s O(log n).

  • Time complexity: how many basic steps an algorithm takes, as a function of the input size n. We count steps, not seconds, because seconds depend on the computer.
  • Space complexity: how much extra memory it needs, as a function of n. Space = fixed part (code, simple variables) + variable part (arrays, recursion stack).

Best, average and worst case

Take linear search in an array of n items:

CaseWhenComparisons
BestThe key is the first element1 → O(1)
AverageThe key is somewhere in the middleabout n/2 → O(n)
WorstThe key is last, or not presentn → O(n)

We usually quote the worst case, because it’s a guarantee.

Asymptotic notations

“Asymptotic” means “what happens when n gets very large”. Three notations describe it:

Big-O: O(g(n))

Upper bound, the worst case. f(n) = O(g(n)) if there are constants c > 0 and n₀ such that f(n) ≤ c·g(n) for all n ≥ n₀.

“It will never be slower than this.”

Omega: Ω(g(n))

Lower bound, the best case. f(n) = Ω(g(n)) if f(n) ≥ c·g(n) for all n ≥ n₀.

“It will never be faster than this.”

Theta: Θ(g(n))

Tight bound, the exact growth. f(n) = Θ(g(n)) if c₁·g(n) ≤ f(n) ≤ c₂·g(n) for all n ≥ n₀.

“It grows exactly like this.”

How to find the Big-O of any algorithm

  1. Count how many times the innermost statement runs, in terms of n.
  2. Keep only the biggest term: 3n² + 5n + 7 → n².
  3. Drop constants: 4n → n, n/2 → n.
  4. Loops one after another add (n + n = O(n)). Loops one inside another multiply (n × n = O(n²)).
  5. A loop that halves or doubles its counter runs log₂ n times → O(log n).
