Part 1

Tree basics and terminology

A tree is a non-linear, hierarchical data structure: a set of nodes connected by edges, with one special node called the root and no cycles.

A family tree drawn upside down. The great-grandparent (root) is at the top. Children hang below their parents. People with no children are the leaves. Or think of folders on your laptop: C: drive → Documents → College → DSA.

TermMeaning
RootThe top node. It has no parent.
EdgeThe link between a parent and a child. A tree with n nodes has n − 1 edges.
Parent / childA node directly above / directly below another.
SiblingsChildren of the same parent.
Leaf (external node)A node with no children.
Internal nodeA node with at least one child.
DegreeNumber of children of a node. Degree of a tree = maximum degree of any node.
Level / depthNumber of edges from the root (root is level 0; some books start at 1).
HeightNumber of edges on the longest path from a node down to a leaf. Height of tree = height of root.
Ancestor / descendantAny node on the path above / below.
SubtreeA node together with all its descendants.

Binary trees

A binary tree is a tree where every node has at most 2 children, called the left child and the right child.

Full (strict) binary tree

Every node has 0 or 2 children, never exactly 1.

Complete binary tree

Every level is full except possibly the last, which is filled from the left.

Perfect binary tree

All internal nodes have 2 children and all leaves are on the same level.

Skewed tree

Every node has only a left child (left-skewed) or only a right child (right-skewed). It is really a linked list.

Properties (with height h counted in edges)

  • Maximum nodes at level i = 2i.
  • Maximum nodes in a binary tree of height h = 2h+1 − 1.
  • Minimum height for n nodes = ⌈log₂(n + 1)⌉ − 1.
  • In a full binary tree, leaves = internal nodes + 1.

Representing a binary tree

Array (sequential)

Store the root at index 0. For a node at index i: left child at 2i + 1, right child at 2i + 2, parent at ⌊(i − 1)/2⌋. Good for complete trees, wasteful for skewed ones.

Linked

Each node is a structure with three members: [ left | data | right ]. Missing children are NULL. Works for any shape.

Part 2

Tree traversals

A traversal visits every node exactly once. The name tells you when the root is printed.

TraversalOrderFor the tree below
PreorderRoot → Left → Right50 30 20 40 70 60 80
InorderLeft → Root → Right20 30 40 50 60 70 80
PostorderLeft → Right → Root20 40 30 60 80 70 50
Level orderLevel by level, left to right (queue)50 30 70 20 40 60 80

Pre = first, In = in the middle, Post = last: that’s where the root goes. Trick for drawing it by hand: trace a line around the tree starting left of the root. Preorder prints a node when you pass its left side, inorder when you pass underneath, postorder when you pass its right side.

Recursive algorithms
  1. Preorder(node): if node is NULL return; visit node; Preorder(left); Preorder(right).
  2. Inorder(node): if node is NULL return; Inorder(left); visit node; Inorder(right).
  3. Postorder(node): if node is NULL return; Postorder(left); Postorder(right); visit node.
  4. Level order: put root in a queue; while the queue is not empty: dequeue a node, visit it, enqueue its left and right children.

Inorder of a binary search tree always comes out sorted. Use it to check your BST answers in the exam.

Part 3

Binary search tree (BST)

In a BST, every node’s left subtree has smaller keys and its right subtree has bigger keys.

The “guess my number” game. “Is it bigger than 50?” “Yes.” “Bigger than 75?” “No.” Each answer throws away half of the possibilities. A BST stores data so that every search is that game.

Search(key)
  1. Start at the root.
  2. If key == node: found.
  3. If key < node: go left, else go right.
  4. If you reach NULL: not found.
Insert(key)
  1. If the tree is empty, the key becomes the root.
  2. Otherwise compare as in search, going left or right.
  3. When the spot you need is NULL, attach the new node there.
Delete(key): 3 cases
  1. Leaf: just remove it.
  2. One child: link the parent straight to that child.
  3. Two children: replace the key with its inorder successor (smallest key in the right subtree), then delete the successor.

Worked example: insert 45, 15, 79, 90, 10, 55, 12, 20, 50

Show every insertion

Complexity: search, insert and delete take O(h) where h is the height. That is O(log n) for a balanced tree but O(n) for a skewed one, which is why AVL trees exist.

Part 4

Constructing a tree from traversals

Preorder or postorder tells you who the root is. Inorder tells you who goes left and who goes right.

Seating a family photo. One list tells you who is the eldest of each group (the root). The other list is the left-to-right order in the photo (inorder): everyone left of the eldest belongs to the left group, everyone right of them to the right group.

Algorithm (inorder + preorder)
  1. The first element of preorder is the root.
  2. Find the root in the inorder list. Elements to its left form the left subtree, elements to its right form the right subtree.
  3. Take the next element of preorder: it is the root of the left subtree. Repeat steps 2–3 for it.
  4. When the left subtree is done, continue with the right subtree.

With inorder + postorder the only change: take roots from the end of postorder, and build the right subtree before the left.

You always need inorder. Preorder + postorder alone can’t tell left from right when a node has only one child, so they don’t give a unique binary tree.

Worked example

Inorder: D B E A F C   Preorder: A B D E C F

Constructing a BST from a sequence

If the question gives just a list of numbers and says “construct a binary search tree”, insert them one by one with the BST rule (smaller left, bigger right), as in Part 3.

Part 5

AVL trees: self-balancing BSTs

An AVL tree is a BST where, for every node, the heights of the left and right subtrees differ by at most 1.

A BST built from 10, 20, 30, 40, 50 becomes a straight line (skewed), so searching is as slow as a linked list. An AVL tree is a BST with a rule that keeps it from leaning: whenever one side gets too heavy, it rotates to rebalance, like shifting books so a shelf doesn’t tip over. Named after its inventors Adelson-Velsky and Landis.

BF(node) = height(left subtree) − height(right subtree). In an AVL tree every BF is −1, 0 or +1. If any BF becomes +2 or −2, rotate.

The four cases and their rotations

Find the lowest node that became unbalanced. Look at the path from it towards the newly inserted node: the first two steps name the case.

CaseNew key went…BF of unbalanced nodeFix
LLLeft, then Left+2One right rotation
RRRight, then Right−2One left rotation
LRLeft, then Right+2Left rotation at the child, then right rotation
RLRight, then Left−2Right rotation at the child, then left rotation

Rotate the opposite way to the lean. Leaning left (LL) → rotate right. Leaning right (RR) → rotate left. For a zig-zag (LR or RL), first straighten the zig-zag with a rotation at the child, then do the single rotation.

LL: insert 30, 20, 10
RR: insert 10, 20, 30
LR: insert 30, 10, 20
RL: insert 10, 30, 20

The general rotation in words. Right rotation at Z: Z’s left child Y moves up into Z’s place; Z becomes Y’s right child; Y’s old right subtree becomes Z’s new left subtree. Left rotation is the mirror image. Everything stays in BST order.

AVL insertion algorithm
  1. Insert the key exactly as in a BST.
  2. Walk back up from the new node, updating heights and balance factors.
  3. At the first node whose BF is +2 or −2, identify the case (LL, RR, LR, RL) and apply its rotation.
  4. After one (single or double) rotation, the whole tree is balanced again.

Worked example: 50, 20, 60, 10, 8, 15, 32, 46, 11, 48

Show every insertion with balance factors

Deletion works the same way: delete as in a BST, then walk up and rotate wherever a BF becomes ±2 (you may need more than one rotation on the way up). Complexity: search, insert, delete are all O(log n) because the height stays about log₂ n.

Part 6

B-trees

A B-tree is a balanced multi-way search tree: each node can hold several keys and have many children, and all leaves are on the same level.

A library catalogue. Instead of a yes/no question at each step (binary), each drawer label splits the books into many ranges: A–F, G–M, N–S, T–Z. Fewer steps to reach the right shelf. Databases and file systems use B-trees because reading from disk is slow, and a short, wide tree needs very few disk reads.

Properties of a B-tree of order m

  1. Every node has at most m children and at most m − 1 keys.
  2. Every internal node except the root has at least ⌈m/2⌉ children (so at least ⌈m/2⌉ − 1 keys).
  3. The root has at least 2 children (unless it is a leaf).
  4. All leaves are on the same level (the tree is always perfectly balanced).
  5. Keys inside a node are in sorted order, and a node with k keys has k + 1 children. Keys in the i-th child lie between the (i−1)-th and i-th keys of the parent.

Insertion algorithm
  1. Search for the key’s place: start at the root and go down to the correct leaf.
  2. Insert the key into that leaf in sorted order.
  3. If the leaf now has m keys (one too many), split it: the median key moves up into the parent, the keys left of it form one node, the keys right of it form another.
  4. If the parent now overflows, split it the same way. Repeat upwards.
  5. If the root splits, the median becomes a new root and the tree grows one level taller. B-trees grow at the top, never at the bottom.

Worked example: order 5

Insert C N G A H E K Q M F W L T Z D P R X Y S into a B-tree of order 5 (max 4 keys per node).

Deletion in brief

  • Delete from a leaf. If the key is in an internal node, swap it with its inorder predecessor or successor (which is in a leaf) first.
  • If the leaf now has too few keys: borrow a key from a sibling through the parent, if the sibling has a spare.
  • Otherwise merge the leaf with a sibling and pull the separating key down from the parent. This can shrink the tree’s height.

B-tree vs B+ tree

B-treeB+ tree
Data can be stored in any nodeData is stored only in the leaves
Leaves are not linkedLeaves are linked, so range queries are fast
Keys appear onceInternal keys are copies used as signposts

Applications: database indexes (MySQL, Oracle), file systems (NTFS, ext4), anything stored on disk. Complexity: search, insert and delete are O(log n).

Two classic mistakes: inserting a new key into an internal node (always insert into a leaf), and forgetting that splitting pushes the median up instead of the new key.

Part 7

Hashing and collision resolution

Hashing uses a hash function to turn a key directly into an array index, so search, insert and delete take O(1) on average.

Lockers at the gym. Your locker number is your roll number mod 100: roll 2345 → locker 45. You walk straight to it, no searching. But roll 1245 also maps to locker 45. That clash is a collision, and collision resolution is the rule for where the second person goes.

TermMeaning
Hash tableThe array that stores the keys. Each position is a slot or bucket.
Hash function h(k)Turns a key into a slot number between 0 and m − 1.
CollisionTwo different keys get the same slot.
Load factor αα = n / m (keys stored ÷ table size). Lower α → fewer collisions.

Hash functions

  1. Division: h(k) = k mod m. Choose m as a prime. The most common in exams.
  2. Mid-square: square the key and take the middle digits. 123² = 15129 → middle “1” or “51”.
  3. Folding: split the key into parts and add them. 123456 → 123 + 456 = 579.
  4. Multiplication: h(k) = ⌊m × (k·A mod 1)⌋ with 0 < A < 1 (often A ≈ 0.618).

A good hash function is quick to compute, spreads keys evenly over the table, and causes few collisions.

Collision resolution techniques

1. Separate chaining (open hashing)

Each slot holds a linked list. Colliding keys are added to that slot’s list. The table never “fills up”.

2. Open addressing (closed hashing)

All keys live inside the table itself. On a collision, probe other slots until a free one is found:

  • Linear probing: h, h+1, h+2, … → (h + i) mod m
  • Quadratic probing: h, h+1, h+4, h+9, … → (h + i²) mod m
  • Double hashing: (h1(k) + i·h2(k)) mod m, with a second hash such as h2(k) = R − (k mod R)

Clustering and rehashing

  • Primary clustering (linear probing): occupied slots bunch together in long runs, so new keys take longer and longer to place. See how 92 and 101 had to walk past a cluster above.
  • Secondary clustering (quadratic probing): keys with the same home slot follow the same probe sequence. Double hashing avoids both.
  • Rehashing: when the load factor gets too high (say α > 0.7), create a bigger table (about double size, a prime) and re-insert every key with the new hash function.

Part 8

Spanning trees

A spanning tree of a connected graph is a subgraph that includes every vertex, is connected, and has no cycle.

A town has many possible roads between 4 villages. The council only needs enough roads so that every village can reach every other one, with no road that makes a loop (a loop means one road was unnecessary). That minimal road network is a spanning tree.

Properties

  • A graph with n vertices has spanning trees with exactly n − 1 edges.
  • It has no cycles. Adding any one more edge creates a cycle.
  • Removing any one edge disconnects it (it is “minimally connected”).
  • A connected graph can have many spanning trees. A disconnected graph has none.
  • A complete graph with n vertices has nn−2 spanning trees (Cayley’s formula). K₄ has 4² = 16.

In a weighted graph, the MST is the spanning tree whose total edge weight is the smallest. Two famous algorithms find it: Prim’s and Kruskal’s (Q25).

Applications: designing cable, road, water or electricity networks at minimum cost; network routing protocols (avoiding loops); cluster analysis; approximate solutions to the travelling salesman problem.
