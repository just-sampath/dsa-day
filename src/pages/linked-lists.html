Linked lists: singly, doubly, circular

A linked list is a chain of little boxes, each one pointing to the next. You’ll see why that beats an array for inserting and deleting, and you’ll perform every operation yourself, pointer by pointer.

Part 1

Why do we need linked lists?

A linked list is a chain of nodes, where each node stores data and the address of the next node.

A treasure hunt. Each clue (node) has a message (data) and tells you where the next clue is hidden (the pointer). The clues can be anywhere in the city; they don’t need to sit side by side. You only need to know where the first clue is (that’s head). The last clue says “The end” (that’s NULL).

The problem with arrays

  • Fixed size. int a[100] stays 100 forever: wasted space or not enough.
  • Slow insert/delete in the middle. To insert at position 2 you must shift every later element one place right. 1000 elements → up to 1000 shifts.
  • An array needs one continuous block of memory.

A linked list fixes all three. Nodes are created with malloc only when needed, they can sit anywhere in memory, and inserting means changing two pointers, no shifting.

The node

Each node is a structure (from Q21) with two members. The second one is a pointer to the same kind of structure, which is why this is called a self-referential structure.

Array vs linked list

ArrayLinked list
Fixed size (static)Grows and shrinks (dynamic)
Continuous memoryNodes scattered anywhere, joined by pointers
Direct access: a[i] in O(1)Must walk from head: O(n) to reach the i-th node
Insert/delete in middle: O(n) shiftingInsert/delete: change pointers, O(1) once you are there
No extra memory per elementExtra memory for the pointer in every node

Three types

Singly (SLL)

Each node points to the next one only. Travel in one direction.

Doubly (DLL)

Each node points to next and previous. Travel both ways.

Circular (CLL)

The last node points back to the first. No NULL, it loops.

Part 2

Singly linked list: every operation

Every operation is just moving a pointer called temp and re-pointing one or two arrows.

The golden rule of insertion: connect the new node to the list first (newNode→next = …), and only then change the old pointer. If you change the old pointer first, you lose the rest of the list. Try both orders in your head with the playground below.

Insertion algorithms

Insert at beginning O(1)
  1. Create newNode, store the data.
  2. newNode→next = head.
  3. head = newNode.
Insert at end O(n)
  1. Create newNode, data in, newNode→next = NULL.
  2. If head == NULL: head = newNode, stop.
  3. temp = head; while temp→next ≠ NULL: temp = temp→next.
  4. temp→next = newNode.
Insert at position pos O(n)
  1. If pos == 1, insert at beginning.
  2. Create newNode.
  3. temp = head; move temp forward pos − 2 times (it stops at node pos − 1).
  4. newNode→next = temp→next.
  5. temp→next = newNode.

Deletion algorithms

Delete from beginning O(1)
  1. If head == NULL: “underflow”, stop.
  2. temp = head.
  3. head = head→next.
  4. free(temp).
Delete from end O(n)
  1. If head == NULL: stop. If only one node: free(head), head = NULL, stop.
  2. temp = head; while temp→next→next ≠ NULL: temp = temp→next.
  3. free(temp→next).
  4. temp→next = NULL.
Delete at position pos O(n)
  1. If pos == 1, delete from beginning.
  2. temp = head; move it to node pos − 1.
  3. del = temp→next.
  4. temp→next = del→next.
  5. free(del).

Traversal and search

Traverse (display) O(n)
  1. temp = head.
  2. While temp ≠ NULL: print temp→data; temp = temp→next.
Search for key O(n)
  1. temp = head, pos = 1.
  2. While temp ≠ NULL: if temp→data == key, report pos and stop; else temp = temp→next, pos++.
  3. If the loop ends, the key is not found.

Forgetting the empty list case (head == NULL) and the single node case. Examiners look for them. Always write “If head == NULL, print underflow” as the first step of any delete.

Part 3

Doubly linked list (DLL)

Each node has two pointers: prev to the node before it and next to the node after it.

A train. Every coach is coupled to the coach in front and the coach behind, so you can walk through it in either direction. A browser’s Back and Forward buttons work the same way.

Algorithms

Insert at beginning
  1. Create newNode; newNode→prev = NULL.
  2. newNode→next = head.
  3. If head ≠ NULL: head→prev = newNode.
  4. head = newNode.
Insert at end
  1. Create newNode; newNode→next = NULL.
  2. If head == NULL: newNode→prev = NULL, head = newNode, stop.
  3. Walk temp to the last node.
  4. temp→next = newNode.
  5. newNode→prev = temp.
Insert after node temp (position pos)
  1. Walk temp to node pos − 1.
  2. newNode→next = temp→next; newNode→prev = temp.
  3. If temp→next ≠ NULL: temp→next→prev = newNode.
  4. temp→next = newNode.
Delete node temp (any position)
  1. Walk temp to the node to delete.
  2. If temp→prev ≠ NULL: temp→prev→next = temp→next, else head = temp→next.
  3. If temp→next ≠ NULL: temp→next→prev = temp→prev.
  4. free(temp).
  • Traverse in both directions.
  • Delete a node when you only have a pointer to it (you can reach the previous node through prev).
  • Insert before a given node easily.
  • Extra memory: one more pointer per node.
  • Every insert/delete must update four links instead of two, so more chances to make a mistake.

Part 4

Circular linked list (CLL)

The last node points back to the first, so the list forms a circle and has no NULL.

Players sitting in a circle playing a card game: after the last player, the turn goes back to the first. A music playlist on repeat all and the CPU giving each program a turn (round robin) work the same way.

Traversal can’t use while (temp != NULL): there is no NULL, so it would loop forever. Stop when you get back to head: do { print; temp = temp→next; } while (temp != head);

Algorithms

Insert at beginning
  1. Create newNode.
  2. If head == NULL: newNode→next = newNode; head = newNode; stop.
  3. Walk temp to the last node (temp→next == head).
  4. newNode→next = head.
  5. temp→next = newNode.
  6. head = newNode.
Insert at end
  1. Create newNode.
  2. If head == NULL: newNode→next = newNode; head = newNode; stop.
  3. Walk temp to the last node.
  4. temp→next = newNode.
  5. newNode→next = head.
Delete from beginning
  1. If head == NULL: underflow, stop.
  2. If head→next == head (one node): free(head); head = NULL; stop.
  3. Walk last to the last node.
  4. temp = head; head = head→next.
  5. last→next = head.
  6. free(temp).
Delete from end
  1. If empty or one node: as above.
  2. Walk temp to the second-last node (temp→next→next == head).
  3. free(temp→next).
  4. temp→next = head.

Circular doubly linked list: a DLL where the last node’s next points to the first and the first node’s prev points to the last. You can loop in both directions.

Applications of linked lists

  • Implementing stacks and queues
  • Dynamic memory management (free-block lists)
  • Polynomial representation and addition
  • Adjacency lists for graphs (Q25)
  • Undo/redo and browser back/forward (DLL)
  • Music playlists on repeat, round-robin scheduling (CLL)
  • Hash table chaining (Q24)
  • Image viewers: next and previous photo (DLL)
  • Dynamic size, no waste
  • Fast insert/delete (no shifting)
  • No need for continuous memory
  • No direct access: reaching the i-th node is O(n)
  • Extra memory for pointers
  • Reverse traversal is hard in an SLL
